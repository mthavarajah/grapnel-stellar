# Solver-backed Testnet settlement — owner revision, November12

The owner authorized a two-pool intent/solver model and Freighter for Perpetuals. This is settlement across separately funded Testnet pools, not a physical crosschain bridge. Circle CCTP support exists with account restrictions; this architecture avoids dependence on that route without claiming it does not exist.

The existing Privy session identifies the fintech customer. A separate SEP53 Freighter proof binds that customer/tenant/identity-wallet to a possibly different Stellar address. Freighter signs the customer's exact deposit payment and exact order/withdrawal messages; ordinary Privy wallet APIs are unchanged. No business key alone authorizes spending. No customer EVM wallet or private key export is required.

Stellar USDC stays in a fixed server-controlled Testnet treasury. The selected issuer is pinned per deployment; the current application's GATALT-issued USDC and Circle's canonical Testnet USDC are distinct. Only confirmed exact escrow payments can progress. Provider collateral is allocated from an actual prefunded Hyperliquid Testnet master to a unique customer subaccount. No SQL trading credit becomes spendable before both source payment and actual provider cash transfer are verified. Subaccounts must be verified under the configured master; no shared unsegregated customer positions.

Master signatures bind the subaccount/vaultAddress. Nonces and signed provider actions are persisted globally per master before one-use send claims. Orders require current Freighter approval, fresh source metadata, available collateral and current entitlements. Fills and position deltas—not acknowledgements—establish execution. Withdrawals require a separate exact Freighter claim, authoritative withdrawable provider collateral, verified return to the master and an actual Stellar treasury payout to the bound Freighter address. PnL/fees affect settlement; unavailable treasury liquidity blocks preparation rather than creating funds. Timeouts retain hashes/nonces and reconcile first.

Lead freeze: `modules/solver/contracts.ts`, migration0008. Lead owns routes/runtime/migrations, API agent owns solver persistence only, chain agent owns Freighter proof helpers, Hyperliquid agent owns master/subaccount adapter only, UI agent owns the solver card only. Existing B2B module identifiers remain unchanged. Separate Stocks token execution is not satisfied by stock perpetuals and requires its own provider/reference-token decision.

No deposits, provider allocations, trades or payouts are claimed. Real Testnet master liquidity/signing configuration and operator access prerequisites remain external acceptance requirements. Mainnet writes, hosted-interface restriction bypasses, fake balances and invented transaction evidence remain prohibited.
