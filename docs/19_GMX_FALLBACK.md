## Stocks-style customer flow — November 13

Perpetuals uses the same embedded wallet and compact ticket/progress dialog as Stocks. Long/Short are green/red, selected direction remains visible, balances sit beside the action, and an exact collateral approval automatically precedes the original order when needed. Network selection happens before preparation. An explicit Retry continues that same unsigned request and original in-memory trade intent. Passive recovery never signs. After a reload without the original trade intent, recovering an approval completes only that approval; a fresh Long/Short click supplies the new order intent.

Get funds combines the existing capped native Testnet gas grant with a customer-signed100USDC.SG mint. The preexisting controlled QA Testnet account is configured server-side as the capped gas treasury; no secret is shipped to the browser. It does not convert Stellar USDC. The wallet's exact verified USDC.SG balance is shown in Overview/Funds with reserved0, available equal to balance, and the explicit Testnet settlement-unit valuation. Real terminal perp events refresh these holdings. Selected-market open positions show actual size/collateral and reference-mark PnL/equity estimates; these omit accrued funding, borrowing, execution impact and close fees and do not establish a guaranteed close payout.

Order creation remains pending until actual keeper execution and position change. Client polling and a read-only server reconciler independently recover retained hashes, including when the dialog closes. Signing guards the current wallet/market before and after the SDK call; an ambiguous submission recovers its existing hash. Only actual returned signatures are marked attempted. Initial read failures keep neutral reconnecting state.

The production adapter explicitly selects canonical token-event confirmation for mint/approval, validating the exact mined body, current registry, canonical two-confirmation receipt and exact event. Proof basis is `canonical_token_event` with `balanceDeltaAtomic6` for mint or `allowanceAtomic6` for approve; historical before/after values are not invented. The original historical-state mode remains the default and its negative delta test remains intact. Store and browser independently check the event proof effect. This avoids stranded funding/approval requests on a pruned public RPC.
