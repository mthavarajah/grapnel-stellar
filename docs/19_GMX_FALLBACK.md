An order creation receipt is not a fill.

The default public RPC prunes historical contract state; the alternate public archive reader requires credentials. Existing historical-state verifier and its negative tests are retained. The runtime uses the explicit event-state verifier: independently re-derive each exact creation transaction; verify canonical, successful, two-confirmation keeper receipts, registered event emitter/handler, exact account/market/collateral/side/order/position keys; prove `PositionIncrease` size0→20 and `PositionDecrease`20→0 from actual emitted sizeDeltaUsd/sizeInUsd; require strictly ordered executions and current real Reader absence.
